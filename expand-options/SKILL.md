# expand-options — 增加选项技术

## R — 原文

> 如果只能选择 yes 或者 no,从长期来看,你有 52% 的决定都是错的。如果你能增加一两个选项,那么选错的比率就下降到 32%。
>
> 哪怕大多数人都失败的局面下,也总会有几个人是成功的,那你就看看那几个成功者是怎么做的。这个借鉴的思路,叫做"寻找亮点"。
>
> — 希思兄弟《决断》(万维钢解读，第2讲)

---

## I — 方法论骨架

当用户卡在 yes/no 二元选项里(选 A 还是 B、做还是不做),有三层递进的加选项技术:

**第一层:加"假选项"也能改善** — 加一条废话选项如"什么都不做""延期再决""省钱花别处",只要打破二元框架,决策质量都会上升(DVD 实验 80%→55%)。原理:用户意识到"还有别的选择"本身就是杠杆。

**第二层:借鉴** — 别自己空想,看别人怎么做的。先内部找亮点(本组织/身边谁做过类似的事,怎么做的),再看同行(同行业/同领域其他人怎么做),最后跨领域找(其他领域遇到类似问题的解法)。沃尔玛说"我每个动作都是从别人那里抄来的"。

**第三层:寻找亮点** — 在多数人失败的领域里,找少数成功的案例学。越南儿童营养不良案例中,营养学家没粮援的情况下,向"贫穷但孩子健康"的越南家庭学喂小鱼小虾,一分钱没花解决问题。这是进化论式的搜索:不预设立场,让成功尝试自然胜出。

实操顺序:先加废话选项(快)→借鉴(中)→寻找亮点(慢但最有力)。三层不必全做,问题越陌生越要走到第三层。

## A1 — 书中的应用

### 案例 1:越南儿童营养不良
- **问题**: 越战刚结束,儿童严重营养不良,但国际组织没粮援
- **方法论的使用**: 美国营养学家没粮援可发,借鉴越南人自己;深入农村找"亮点"——同样穷但孩子健康的家庭,发现他们喂小鱼小虾;召集村民开会请这些家长传授经验
- **结论**: 不需要外援,越南人自己就有解法
- **结果**: 两名营养学家一分钱没花,儿童营养不良问题解决

### 案例 2:校长解决学生排队打饭
- **问题**: 学校中午学生排队时间长
- **方法论的使用**: 希斯兄弟的方案:① 先看内部有没有"亮点"(哪个窗口队列特别快)② 再看同行(别的学校食堂怎么做)③ 再跨领域(银行、商店等排队场景)
- **结论**: 按"先内后外再跨"的顺序搜索,能最快找到可行解
- **结果**: 验证"三步搜索顺序"作为借鉴的程序化模板

### 案例 3:沃尔玛借鉴同行
- **问题**: 沃尔玛如何做大
- **方法论的使用**: 沃尔玛老板说"我每个动作几乎都是从别的商店那里抄来的"
- **结论**: 借鉴不是可耻的事,借鉴得多了就自成一家
- **结果**: 沃尔玛成为零售巨头

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户问"我该怎么办"但只能列出 2 个选项
2. 用户面临全新领域问题,不知道怎么下手
3. 用户在多数人失败的领域(如创业、教育改革)想找突破
4. 用户读完别人案例想"借鉴到自己的场景"

### 语言信号

- "我除了这条没别的办法"
- "只有两个选择 A 和 B"
- "想跳出来"
- "在 X 这个领域有没有人成功过?"
- "我能不能借鉴别人的做法?"

### 与相邻 skill 的区分

- 与 `decision-is-choice`: 后者是"识别无选项",本 skill 是"怎么加选项"。**前者触发本 skill**
- 与 `decision-four-step`: 本 skill 是第一步"扩充选项"的专门技术,常被前者委派
- 与 `compare-side-by-side`: 本 skill 生成选项,后者处理如何呈现/比较选项

## E — 可执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **加废话选项(快速破二元)**
   - 完成标准: 用户列出至少 3 个备选(可以包含"什么都不做""延期 3 个月")
   - 判停条件: 用户已列出 ≥ 3 个真实备选 → 跳到 `compare-side-by-side`

2. **借鉴程序(找现成做法)**
   - 完成标准: 用户至少找到 1 个"别人在我类似情境下是怎么做的"案例
   - 子步骤:
     - 先内部: 你身边/本组织/你的朋友里,谁做过类似的事?他们怎么做?
     - 同行: 同行业/同领域其他人怎么做?
     - 跨领域: 其他领域遇到类似问题的解法?

3. **寻找亮点(突破性搜索)**
   - 完成标准: 用户在"多数人失败的领域"找到至少 1 个"少数成功者"案例并借鉴其做法
   - 触发条件: 当问题很陌生、借鉴仍无解、或用户在多数人失败的领域

   🔴 **CHECKPOINT**: 找亮点时不要预设"哪些做法可行",让成功尝试自然胜出(进化论色彩)。如果用户预先排除某些选项,提示他"也许这就是亮点该出现的地方"

### if-fail 三段式兜底

| 失败信号 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 用户找不到任何成功案例 | 改问"谁**没**失败?"——分析边界条件 | 若领域真无先例,标注为"全新增量",调 `base-rate-forecast` 强化预测 |
| 借鉴来的做法不适合自己 | 加一句"为什么他们这样做在我这里不行?",列出 1-3 个边界条件 | 调 `reality-check` 评估借鉴可行性 |
| 加了 5+ 选项陷入瘫痪 | 用 🛑STOP: 选项够用就好,3-5 个是甜区。再多就选不出(选择悖论 ce18) | 调 `compare-side-by-side` 用统一比较收紧 |

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **不可逃避的单行道**: 物理定律/截止日期/已签合同,加选项是浪费时间
- **选项已经足够(≥ 3 个真实备选)**: 直接进入比较和评估,不要无谓加选项
- **纯执行细节**: 已经决定做什么,怎么做不是本 skill 的事
- **纯道德选择**: 没有"借鉴"可解的道德困境(如是否告发亲人),不要强行套用

### 作者在书中警告的失败模式

- **「伪选项」(ce12)**: 尼克松幕僚给两个不可行选项当陪衬。加了选项但都不是真选项
- **「无意识的单选项」(ce14)**: DVD 实验揭示,只要"意识到"有别的选项,决策就改善
- **「逐个评估」(ce13)**: 选项要**同时摆出**比较,不要加完又逐个看
- **「选择悖论」(ce18)**: 选项过多反而瘫痪,3-5 个是甜区

### 作者的盲点 / 时代局限

- **"借鉴"假设有可借鉴对象**: 在全新增量场景(没人做过),借鉴失效。这是 BOOK_OVERVIEW 批判段指出"被动决策法"的边界
- **"找亮点"假设成功者可观察**: 很多成功有偶然性(运气、时机),不能复制。需配合 `base-rate-forecast` 评估基线成功率
- **跨领域借鉴的过度风险**: 把 A 领域的做法搬到 B 领域可能完全失效(如把互联网公司"快速迭代"搬到核电站)。需 `reality-check` 求证

### 容易混淆的邻近方法论

- **头脑风暴**: 类似"加选项",但头脑风暴强调数量不强调"借鉴真实成功者"
- **「创造更多选项」(Option Generation in design thinking)**: 类似但更聚焦设计场景
- **SWOT 分析**: 列内外因素但不"找亮点",不是真正的加选项技术
