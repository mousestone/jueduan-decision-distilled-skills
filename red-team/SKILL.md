# red-team — 蓝军反对派

## R — 原文

> 一个好办法是每次讨论决策之前,专门制定一支"蓝军"部队,让他们专门唱反调。这个好处是既然他是奉命反对,讨论起来大家就不会觉得他是在反对我这个人,是对事不对人。
>
> — 希思兄弟《决断》(万维钢解读，第3讲)

---

## I — 方法论骨架

无论团队还是个人,**没有反对派的决策是不完整的**,类似庭审只有法官没有辩护律师。但人天然不擅长反对(包括自我反对),因为反对会伤感情、显得不合群。

解法是把"反对"**程序化**:每次讨论决策前,专门指定一个人(或一群人)当**蓝军**——奉命唱反调。关键纪律:

1. **奉命反对**(非自发): 反对是工作不是立场,所以对事不对人
2. **必须给具体理由**(不能泛反对):"我反对"不算数,"我反对,因为 X 数据/经验/逻辑表明 Y 风险"才算
3. **听完所有反对理由后仍决定坚持**,这个决定才算靠谱 — 风投经验:列举所有反对理由后仍投,才值得投

个人决策同样适用:**主动找几个朋友当蓝军**("求骂醒"),用理智战胜情感。蓝军是工作,不是真反对你这个人。

---

## A1 — 书中的应用

### 案例 1:风投公司的反对派经验(《巨人的工具》引用,第3讲)
- **问题**: 风投公司如何避免投错
- **方法论的使用**: 每个决定都设立反对派,要求给具体反对理由;听完所有反对理由仍投才投
- **结论**: 听完全部反对理由后仍坚持的决定才靠谱
- **结果**: 风投公司的投资决策质量提升

### 案例 2:CEO 高溢价收购 (蓝军必要性)
- **问题**: CEO 收购另一个公司时付过高溢价
- **方法论的使用**: CEO 受到媒体吹捧,确认偏误严重,但没有蓝军唱反调(也没有制度要求)
- **结论**: 没有蓝军的决策容易被感情回报主导
- **结果**: 多数收购结果不好

### 案例 3:个人决策找朋友"求骂醒"
- **问题**: 个人重大决策
- **方法论的使用**: 主动找几个朋友提反对意见,朋友"奉命反对"而不是真否定你这个人
- **结论**: 个人决策也适用蓝军机制
- **结果**: 用理智战胜情感,减少确认偏误

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 团队决策没人唱反调(全员支持)
2. 用户对某个方案过于热情/确定,想要反向意见
3. 用户在做个人重大决策(辞职/创业/离婚/置业)
4. 用户在做投资/收购/合作决策,需要独立反对声音

### 语言信号

- "团队里没人反对"
- "我对这个方案太兴奋,想找点反对意见"
- "我该不该做 X"
- "感觉太顺了,有点不踏实"

### 与相邻 skill 的区分

- 与 `reality-check`: 本 skill 是"定向反对派"(指定专人),后者是"广撒网多源求证"。**本 skill 更聚焦、更强制**
- 与 `ten-ten-ten`: 本 skill 是"外部反对",后者是"自己当自己旁观者"
- 与 `decision-four-step`: 本 skill 是第二步"现实检验"的纠偏工具,常被前者委派

## E — 可执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别决策类型**(团队/个人)
   - 完成标准: 用户能说出"团队/个人"决策

2. **团队场景:指定蓝军**
   - 完成标准: 团队里至少 1 人被指定为蓝军,任务是"给具体反对理由"
   - 关键纪律: 蓝军必须是**奉命反对**,不要让蓝军"自发感觉"是否反对

   🔴 **CHECKPOINT**: 若蓝军只说"我反对"但说不出具体理由,提示他:"反对不是工作,具体反对理由才是"

3. **个人场景:找朋友当蓝军**
   - 完成标准: 用户至少找了 1 个朋友,主动告知"我要请你扮演蓝军,给我反对意见"
   - 关键纪律: 朋友要明白是"奉命反对",不是为了真否定你这个人

4. **听完所有反对意见后再决定**
   - 完成标准: 用户明确说出"我听过所有反对意见后,仍决定 X,因为..."

   🛑 **STOP 条件**: 若用户在没听完反对意见时就决定 — 这意味着蓝军机制失效,回到 `reality-check` 重新多源求证

### if-fail 三段式兜底

| 失败信号 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 蓝军给不出具体理由(泛反对) | 提示他:"具体理由是什么?什么数据/经验/逻辑支持你的反对?" | 若实在没有具体理由,这可能意味着原方案真的不错,但仍要标注"反对理由不足" |
| 用户选择性忽略反对意见 | 用 🔴CHECKPOINT: "你听到的是 1 个反对意见就排除,还是听完所有反对才决定?" | 若用户选择性忽略,提醒他确认偏误可能正在发生,调 `reality-check` |
| 朋友"求骂醒"反而捧场 | 换人 — 不是所有人都擅长扮演蓝军 | 若无人可当蓝军,改用 `ten-ten-ten` 自己当自己旁观者 |

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **紧急执行**: 没时间做蓝军机制
- **纯执行细节**: 已经决定怎么做
- **团队文化强烈反对反对**: 蓝军机制可能引发冲突,先调团队文化再调决策机制
- **决策已经被反复推敲**: 蓝军反对可能流于形式,不如直接进入执行

### 作者在书中警告的失败模式

- **「确认偏误」(ce03)**: 蓝军的核心目的是纠这个偏
- **「被荣誉冲昏头脑」(ce04)**: CEO 没有蓝军导致高溢价收购
- **「决策无反对派」(ce11)**: 类似庭审只有法官没有辩护律师
- **「决策瘫痪」(ce16)**: 蓝军机制可能延长决策时间,要平衡反对与决策瘫痪

### 作者的盲点 / 时代局限

- **「奉命反对」假设团队文化接受**: 在权威文化(老板说了算)场景下,蓝军机制可能被视为挑战权威
- **「具体反对理由」假设信息可得**: 实际场景中反对者可能没有足够信息给具体理由
- **个人决策找朋友假设朋友"够狠"**: 实际朋友可能因为面子给不出有力反对

### 容易混淆的邻近方法论

- **「魔鬼代言人」(Devil's Advocate)**: 形式类似但魔鬼代言人强调"扮演",蓝军强调"反对是工作"
- **Pre-mortem(预先验尸)**: 假设方案失败,倒推失败原因 — 比蓝军更聚焦"失败模式"而非"反对意见"
- **六顶思考帽**:Edward de Bono 框架,蓝军是其中"黑帽"(批判)的程序化
