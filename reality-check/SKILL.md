# reality-check — 多源求证/现实检验

## R — 原文

> 这一步人们常犯的错误是"确认偏误"——如果你先入为主已经有了看法,比如说你已经"喜欢"某个选项,你就可能会不顾事实坚持这个选项。而普利斯特里的做法是向很多人寻求意见,对自己的工作前景获得一个客观的评估。
>
> — 希思兄弟《决断》(万维钢解读，第1讲)

---

## I — 方法论骨架

当用户面对"评估方案 X 是否好"、"判断我会不会成功"、"我对某事的看法对不对"这类问题时,最大的敌人是**确认偏误**:先入为主喜欢某个选项就只能听进正面意见。CEO 高溢价收购案例说明:被荣誉冲昏头脑的 CEO 看到每多一篇吹捧报道,下次就多付 4.8% 溢价 — 越有感情回报的事,确认偏误越严重。

破解确认偏误靠**多源求证**,核心是**找不熟悉但更懂行的人**:
- 熟悉的人: 跟你一样的视角,可能和你一样偏
- 不熟悉但更懂的人: 视角独立 + 信息更全

普利斯特里找朋友的建议是"别去",他没听 — 但他接着问了"不太熟悉但更了解谢尔本伯爵的人",发现了解伯爵的人都劝他去。这个"第二步"才是真相。

实操三个动作:
1. **识别"特别想做"或"特别相信"**:先承认自己可能偏
2. **扩大求证范围**:找和你视角不同的人(不一定是熟人)
3. **给反面意见赋权**:听完所有反面意见后,仍坚持,才靠谱

## A1 — 书中的应用

### 案例 1:普利斯特里择业 (多源求证部分)
- **问题**: 谢尔本伯爵 offer 是否接受
- **方法论的使用**: ① 朋友建议"别去"(了解学者独立性的人视角) ② 普利斯特里接着问不太熟悉但更了解伯爵的人,发现"了解伯爵的人都劝去"
- **结论**: 接受 offer
- **结果**: 7 年合作成功,伯爵人品好

### 案例 2:CEO 高溢价收购
- **问题**: CEO 要不要高价收购另一公司
- **方法论的使用**: 研究者发现媒体每多一篇吹捧 CEO 的报道,CEO 收购下一个公司就多付 4.8% 溢价 — 越被吹捧越偏
- **结论**: CEO 严重确认偏误,花的是公司的钱满足自己的感情回报
- **结果**: 多数收购结果不好(惠普收购康柏、Yahoo 一系列收购)

### 案例 3:李振鹏去深圳
- **问题**: 体制内稳定工作 vs 去深圳闯荡
- **方法论的使用**: 用户列举了各种不去的理由,但"一万个坏处都敌不过一个'想'字" — 确认偏误典型
- **结论**: 想去但不科学的决策
- **结果**: 没在书里说,但展示典型失败模式

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户特别想做某事,问要不要做(典型确认偏误入口)
2. 用户在评估方案/标的/合作伙伴,问"X 是不是好"
3. 用户被某人的推荐/媒体报道影响,在判断真假
4. 用户做完决策后总怀疑自己是不是被偏了

### 语言信号

- "我特别想 / 我坚信"
- "我觉得 X 是个好选择,你怎么看?"
- "我朋友/媒体都说 X 好"
- "我是不是过于乐观/悲观?"

### 与相邻 skill 的区分

- 与 `red-team`: 本 skill 是"向外求证"(找视角不同的人),后者是"程序化设立反对派"(指定专人唱反调)。**本 skill 广撒网,后者定向反对**
- 与 `base-rate-forecast`: 本 skill 评估"这个方案好不好",后者评估"我会不会成功"(用基础比率)
- 与 `decision-four-step`: 本 skill 是四步法第二步"现实检验"的专门技术

## E — 可执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别"特别想做"信号**
   - 完成标准: 用户能说出"我对 X 有强偏好 / 我希望它好 / 我被某人说动了"
   - 判停条件: 若用户说"我对所有方案一视同仁",跳到步骤 3

2. **主动列举反面意见**
   - 完成标准: 用户列出至少 3 条这个方案的反面意见(哪怕他觉得不重要)
   - 关键纪律: 反面意见要"具体"(参照 `red-team` 的具体理由要求)

3. **找 2-3 个外部信息源求证**
   - 完成标准: 用户至少咨询 1 个熟悉的人 + 1 个不熟悉但更懂的人
   - 求证时主动问反面意见(不只问"你觉得好不好")

   🔴 **CHECKPOINT**: 如果所有外部信息源都说"好",停 — 可能是你的求证方式有偏。强制自己再找 1 个"可能给反面意见"的人

4. **综合判断**
   - 完成标准: 用户能把所有意见分类(支持/反对/中性),并解释为什么他的判断仍合理

### if-fail 三段式兜底

| 失败信号 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 用户找不到任何反面意见 | 提示"如果有人反对,最可能的反对理由是什么?" | 调 `red-team` 强制设立反对派 |
| 用户求证的人都说"好" | 用 🔴CHECKPOINT: 你的求证对象可能和你一样偏。强制自己找"反对者" | 调 `base-rate-forecast` 用统计基础比率来对冲 |
| 用户评估后仍偏相信原方案 | 检查求证过程是否包含"听过所有反对仍坚持"的纪律 | 若用户没完成这步,提醒他"听完所有反对意见再坚持才算靠谱"(p14) |

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **紧急危机**: 没时间多源求证
- **纯事实查询**: "北京到上海多远" 不需要多源
- **用户在执行细节**: 已经决定,怎么做不是本 skill
- **用户对领域已是公认专家**: 求证可能反而引入噪声(但要警惕"专家偏" — 专家也是人)

### 作者在书中警告的失败模式

- **「确认偏误」(ce03)**: 只想听正面意见
- **「被荣誉冲昏头脑」(ce04)**: CEO 高溢价收购案例
- **「基础比率 vs 试水矛盾」(ce19)**: 求证结果可能鼓励"再多调研"但实际需要行动 — 这是 BOOK_OVERVIEW 批判段指出的内部矛盾
- **「伪特殊因素」(ce08)**: 求证时拿不出可举证的特殊理由,只是在"自我感觉特殊"

### 作者的盲点 / 时代局限

- **求证假设信息可得**: 实际很多场景无法多源求证(黑箱市场/唯一供应商)
- **求证假设对方诚实**: 实际求证对象可能有自己的利益(投资顾问推产品)
- **「找不熟悉但更懂的人」实践难**: 这种人往往不主动出现,需要用户主动经营网络

### 容易混淆的邻近方法论

- **「兼听则明」**: 同义但缺少"识别确认偏误"的具体信号
- **专家咨询**: 求证但可能引入"专家偏" — 专家也是人,有自己的利益
- **尽职调查(Due Diligence)**: 投资场景的求证,流程化但有时流于形式
