# decision-is-choice — 决策前提检查 (Is this really a decision?)

## R — 原文

> 老江湖和女高中生做决策的最大区别在于老江湖总是考虑多个选项。如果你没有选项,那你那不叫决策,只能叫决心。
>
> — 希思兄弟《决断》(万维钢解读，第2讲)

---

## I — 方法论骨架

科学决策的**前提**是"有多个选项可挑"。如果你面对的局面只有一个出路,那不是决策、是决心;是 yes/no 的二选一,那也不是决策、是钻牛角尖。任何"科学决策四步法"在零选项面前都用不上 — 巧妇难为无米之炊。

这一步看似废话,但实测是普通人最大的盲区:匹兹堡女中学生的调查里,大多数"决定"压根没有备选。她们直来直去"我决定不再指责别人了"、"我要不要跟男朋友分手",从来没想过"我还有没有别的选择? 我能不能把事情改一改?"。哪怕只是**意识到**还有别的选项,决策质量都会显著改善(DVD 实验:80%→55%)。

因此在启动任何决策框架之前,先做这道前提检查:**我手里到底有几个有意义的选项? 是不是只有 yes/no?** 如果是 — 先停下来,花力气给自己"加选项"(参见 `expand-options`)。只有当选项 ≥ 2 个,才进入真正的决策方法。

---

## A1 — 书中的应用

### 案例 1:匹兹堡女中学生调查
- **问题**: 受访的 105 个女中学生过去做过的"决定"绝大多数是单选项(决定做某事)或 yes/no(抽不抽烟、去不去聚会)
- **方法论的使用**: 卡耐基梅隆研究者用这个发现说明"决策=选择"的命题
- **结论**: 大多数年轻人没做过真决策,因为没给自己选项
- **结果**: 同期对比实验显示,能加一两个选项,长期选错率从 52% 降到 32%

### 案例 2:DVD 购买实验
- **问题**: DVD 15 美元,第一组 80% 愿意买
- **方法论的使用**: 第二组加了"废话选项"——"还是把这 15 美元省下来、花到任何你想花的地方去"
- **结论**: 仅仅"意识到自己还有别的选项"就让购买率从 80% 降到 55%
- **结果**: 验证了"选项意识"本身就是决策改善杠杆

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户用"要不要"、"该不该"开头问决策问题
2. 用户列出 A 和 B 两个选项求助,似乎没有第三个备选
3. 用户在重大人生选择面前,但已经预设了"只能走这条路"的思维定式
4. 用户因为没想出第三个选项而陷入 yes/no 纠结

### 语言信号

- "我该不该换工作 / 分手 / 买房 / 创业?"
- "在 A 和 B 之间怎么选?"
- "人生重大选择 / 我要做个大决定"
- "我除了这条路没别的办法了吗?"

### 与相邻 skill 的区分

- 与 `decision-four-step`: 本 skill 是"决策前提检查"(是不是真决策?);后者是"决策框架"(怎么决策)。**先调用本 skill,确认是决策后再调用四步法**
- 与 `expand-options`: 本 skill 是"识别无选项",后者是"加选项的具体技术"。**本 skill 检出无选项 → 调用 expand-options 加选项**
- 与 `values-decision`: 本 skill 在选项生成阶段,后者在选项生成后、利弊算不清时的终局判据

## E — 可执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别用户表述的"选项"数量**
   - 完成标准: 用户的问题中是否列出 ≥ 2 个真正不同的备选? 是 → 直接跳到 `decision-four-step`; 否 → 进入步骤 2

   🔴 **CHECKPOINT**: 若用户的"两个选项"实际是同一选项的两种措辞(如"做"vs"马上做"),要识别为"伪选项",退回步骤 2

2. **自问"我能不能把这件事改一改?"**
   - 完成标准: 用户能列出至少 1 个第三选项(哪怕看起来是废话,如"什么都不做"或"延期再决")
   - 判停条件: 若用户列出 ≥ 2 个真实备选,跳到 `decision-four-step`

   🛑 **STOP 条件**: 如果用户面临的是不可逃避的单行道(物理定律/截止日期/已经签约的合同),本 skill 不能强行"加选项" — 此时承认这是决心不是决策,直接进入执行而非纠结

3. **若仍无选项,调用 `expand-options`**
   - 完成标准: 用户拿到至少 3 个备选后,移交到 `decision-four-step`

### if-fail 三段式兜底(把 B 段失败模式编进 E 段)

| 失败信号 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 用户坚持"真的没别的办法" | 强制问: "你认识的人里谁做过类似的事? 他们有别的办法吗?"(找亮点) | 调用 `expand-options` 走借鉴流程 |
| 用户列出"伪选项"(换汤不换药) | 明确告诉用户这两个是同一选项,要求重新识别真正不同的备选 | 若用户坚持,提醒他这很可能不是真决策,先停下来 |
| 用户陷入"先做后想"的冲动 | 用 🔴CHECKPOINT: "你没选项,这不是决策。先停下,列出第三个选项再继续" | 若用户坚持要立刻行动,标注为"决心"并准备后续纠错成本(`probe-and-pivot`) |

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **紧急危机**(医疗急救、系统宕机):没时间想选项,执行唯一救命方案
- **已经决定后的执行细节**(已经决定创业,怎么做):这是项目管理不是决策
- **纯信息查询类问题**("创业补贴政策"):没有决策在发生
- **不可逃避的单行道**(已经签约、不可逆承诺):别强行"加选项",承认是决心

### 作者在书中警告的失败模式

- **「无选项的决心」(ce01)**: 直来直去的"我要不要 X"被错当成决策,实际是钻牛角尖
- **「伪选项」(ce12)**: 尼克松幕僚糊弄,故意给两个不可行的选项当陪衬,掩盖了真实唯一选项
- **「无意识的单选项」(ce14)**: 用户没意识到"还可以省钱花别处",决策被锁定

### 作者的盲点 / 时代局限

- 「增加选项」并非总是更好 — 选择悖论(选项过多导致决策瘫痪)在 BOOK_OVERVIEW 批判段已指出,本书未处理(ce18)。**调用本 skill 时,选项数应在 2-5 之间,过多反而有害**
- 「决策」的定义略严格,实际场景中很多"选择"介于决策和决心之间;本 skill 给的是"先看是不是真决策"的元判断,不要机械套用

### 容易混淆的邻近方法论

- 鸡汤类"勇敢做决定":强调决心勇气,不问有没有选项,反而强化"无选项的钻牛角尖"
- "二选一思维"训练:只教 yes/no 决策技巧,不教加选项,等于在错误的起点上训练
- **不要把"决策=选择"理解为"凡事都要选",日常琐事就是执行,不要过度激活**
