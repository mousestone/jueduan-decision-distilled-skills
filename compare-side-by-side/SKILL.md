# compare-side-by-side — 同时参选(选项统一摆桌面比较)

## R — 原文

> 你要把多个选项都摆在桌子上,要选就一起参选。……都摆出来,哪个好哪个不好一目了然。一个一个比较,费时费力而且到后面你会忘了前面的。
>
> — 希思兄弟《决断》(万维钢解读，第2讲)

---

## I — 方法论骨架

当用户面前有 ≥ 2 个备选方案,**呈现方式**本身会显著影响决策质量:

- **同时摆出(本 skill 推荐)**:把所有方案的概要一次性呈现,让决策者整体比较。优势:一目了然,前后一致。实验证明效果远好于逐个迭代。
- **逐个迭代(避免)**:提一个方案,反馈,改;再提一个,反馈,改。劣势:到后面会忘前面,容易反复修改陷入决策瘫痪。

希斯兄弟用两组设计小组实验证明:同时摆出方案的组,决策者选得快且更满意;逐个迭代的组,反复修改但决策质量差。

这与体育比赛的"统一打分允许回看录像"原理一致 — 体操比赛一个比完给一个打分,严格来说不科学,因为裁判会遗忘前项。最公平的是所有选手比完,统一回看录像打分。

实操上,把多个方案"同时摆出"不仅是呈现技巧,还隐含**控制感**给决策者:他看到所有选项平等摆出来,知道自己有权选任何一个(古代谋士献上中下三策,也是这个机制)。

---

## A1 — 书中的应用

### 案例 1:设计小组实验
- **问题**: 比较"逐个迭代 vs 同时摆出"哪种呈现方式决策效果好
- **方法论的使用**: 两组设计小组,一组每想出一个方案就给用户看、拿反馈再改;另一组一次性给多个方案同时摆出,让用户选完再略调
- **结论**: 第二组(同时摆出)效果远好
- **结果**: 验证"同时摆出"作为决策呈现技巧的优势

### 案例 2:尼克松三选项
- **问题**: 总统做重大决策
- **方法论的使用**: 尼克松总要求幕僚至少给 3 个选项
- **结论**: 同时摆出多个选项是"老江湖做决策"的核心原则
- **结果**: 幕僚有时故意给 2 个不可行选项当陪衬 — 提示要警惕"伪选项"

### 案例 3:古代谋士献上中下三策
- **问题**: 古代谋士给主公出主意
- **方法论的使用**: 一次性给上策、中策、下策三个方案,主公统一比较
- **结论**: 同时摆出 + 给决策者控制感
- **结果**: 成为古代决策的标准范式

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户有 3-5 个方案要做最终选择
2. 用户在反复修改单个方案,陷入"再来一版"循环
3. 用户已经选了一个但总想着别的,后悔率高
4. 用户在打分/评价多个对象(招聘候选人、产品方案、投资标的)

### 语言信号

- "我有 3 个方案 / 5 个候选人"
- "不知道怎么选"
- "改了好几版还是不满意"
- "选了 A 又想着 B"

### 与相邻 skill 的区分

- 与 `expand-options`: 本 skill 处理"选项呈现",后者处理"如何加选项"。**前者调用后者后才生效**
- 与 `decision-four-step`: 本 skill 是"决策呈现"层,四步法是"决策程序"层
- 与 `values-decision`: 本 skill 给"如何比较",后者给"用什么判据比"

## E — 可执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **要求用户把所有方案一次性列出**(不要逐个给出)
   - 完成标准: 用户能在同一文档/表格里看到所有方案的概要
   - 工具建议: 让用户用表格列出方案 × 评估维度(费用/时间/风险/收益等),或贴方案概要

2. **统一维度评估**
   - 完成标准: 每个方案都被同一组维度打分/比较(避免不同维度混用)
   - 关键纪律: 维度必须**事先定好**,不要看完方案后再设维度(否则会偏向喜欢的那一个)

   🔴 **CHECKPOINT**: 若用户开始说"方案 A 在 X 维度好,方案 B 在 Y 维度好",提示他"先不要做判断,先把所有维度填满再选"

3. **加权打分或取舍**
   - 完成标准: 用户能说出哪个方案总分最高(若用打分) 或 哪个方案"最不能失去什么"(若用取舍法)

   🛑 **STOP 条件**: 若用户说"两个都很好/都很差",停在这里 — 这意味着他没找到区分维度,调 `reality-check` 或 `values-decision` 重设维度

### if-fail 三段式兜底

| 失败信号 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 用户选项数量过多(>7) | 用 🛑STOP: 选项 3-5 个是甜区,过多会瘫痪(选择悖论 ce18)。删减或合并 | 调 `expand-options` 反向操作:删除明显不可行的选项 |
| 用户所有选项看起来一样 | 加一个"什么都不做"的对照基线,强制凸显差异 | 调 `reality-check` 深入评估;若仍无差异,提醒用户这可能不是真决策 |
| 用户选完后总后悔 | 检查用户选的依据 — 若是基于"短期情绪"而非"长远考虑",调 `ten-ten-ten` | 接受后悔是必然,调 `probe-and-pivot` 把决策变成试水(降低承诺) |

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **只有一个方案**: 没有可比较的对象
- **方案之间不可比**: (如"选哪个城市生活"和"该不该换工作"不可放在同一组维度)
- **用户在执行细节上纠结**: 已经选了,怎么做不是本 skill 的事
- **选项过多(>7)**: 先调 `expand-options` 的"找亮点"反向操作来删除

### 作者在书中警告的失败模式

- **「逐个评估」(ce13)**: 一个一个看方案,费时费力且遗忘前项
- **「伪选项」(ce12)**: 幕僚给的两个不可行选项是陪衬,真实唯一选项被掩盖
- **「选择悖论」(ce18)**: 选项过多反而瘫痪,3-5 个是甜区

### 作者的盲点 / 时代局限

- **同时摆出假设方案可"摘要"**: 实际复杂方案难以一句话摘要,摘要过程会丢失关键细节
- **统一维度假设维度可比**: 实际"工作满意度"和"工资"难以直接比较。本 skill 不能解决"不同维度不可公度"的问题
- **决策者单一**: 实际多人决策场景(家庭/团队)不能"控制感"地一次性摆出

### 容易混淆的邻近方法论

- **选秀节目 PK 制**: 两两淘汰,节目效果佳但决策质量差
- **SWOT 矩阵**: 列优劣势但不"统一打分",难做选择
- **决策矩阵(weighted score)**: 类似打分但权重易被主观调整
