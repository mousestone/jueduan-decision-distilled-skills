# probe-and-pivot — 试水法

## R — 原文

> 实干家所谓的所谓的"科学",不是要不要做这件事,而是把握好一开始的力度。拿不准的可以先小规模试探。
>
> 保金斯基提出,用试水的方法创新,有三个原则:尽可能地尝试新事物;尝试要可控,要确保试验不给我们带来灾难性的后果;获得反馈,从结果中学习,随时调整做法。
>
> — 希斯兄弟《决断》(万维钢解读，第5讲)

---

## I — 方法论骨架

当用户面临"重大不确定决策"且决策**可逆**或**错误代价可控**时,不要走"谋定而后动"——这是幻觉。实干的"科学"不在要不要做,而在**把握一开始的力度**:先小规模试探,反馈来再调整。

保金斯基三原则(试水法的操作框架):
1. **尽可能尝试新事物** — 保持实验供给,扩大可能解空间
2. **尝试要可控** — 不带来灾难性后果(单次下注规模要小)
3. **获得反馈并调整** — 反馈闭环是核心,试水不是"做了就算"

适用场景:
- 选专业:先打杂一个月体验(史蒂夫案例)
- 强迫症:分步减少检查次数(佩吉案例)
- 新产品:原型小批量测试市场(企业新产品)
- 创业:最小可行产品(MVP)

不适用:
- 不可逆决策(婚姻/移民/已签约):错误代价不可控
- 错误代价不可控:任何试错可能造成不可恢复损失

**关键纪律**:试水不是"做了就算",而是"做了 → 拿到反馈 → 调整或放弃"的闭环。没有反馈的试水等于没有试水。

## A1 — 书中的应用

### 案例 1:史蒂夫试水药剂师
- **问题**: 史蒂夫喜欢化学,觉得药剂师收入高工时适中,但要投入几年时间和学费
- **方法论的使用**: 没盲目决定,先免费打杂一个月体验药剂师生活
- **结论**: 试水(可控=免费打杂一个月)
- **结果**: 验证试水法的职业选择应用

### 案例 2:佩吉强迫症疗法
- **问题**: 律师事务所女秘书佩吉强迫症,每天带文档回家反复检查
- **方法论的使用**: 治疗师分步减少带回家检查次数,每步确认无损失再下一步,最后故意在文档中犯错确认无人注意
- **结论**: 试水法(可控=分步放松)+ 反馈(每步确认)+ 调整
- **结果**: 强迫症治好

### 案例 3:企业新产品试水
- **问题**: 企业要推全新产品
- **方法论的使用**: 不大批量生产,先做原型小规模试产测市场反应
- **结论**: 反馈好加大,反馈差放弃
- **结果**: 避免大批量生产失败

### 案例 4:斯大林一五计划 (反例)
- **问题**: 斯大林一五计划建世界最大水电站和钢铁厂
- **方法论的使用**: 试图尺度太大、不可控,且不关心反馈(保金斯基调研被无视)
- **结论**: 列宁坝水库效率低,磁山城钢铁厂 1970 年代矿石耗尽,第一年死伤过万工人
- **结果**: 试水尺度失控+无反馈=悲剧

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户想做某事但不确定,问"能不能先试试"
2. 用户面临重大不确定决策(选专业/创业/换城市)
3. 用户在做需要"测试市场"的决策(新产品/新业务)
4. 用户在治疗心理/生理问题需要分步试探

### 语言信号

- "拿不准"
- "能不能先试试 / 试试水"
- "我想做 X 但不确定"
- "不试一下不知道"

### 与相邻 skill 的区分

- 与 `base-rate-forecast`: 后者用"统计预测",本 skill 用"行动反馈"。**两者矛盾,选择标准:可逆选试水,不可逆选基础比率**
- 与 `decision-four-step`: 本 skill 是第四步"为错误做准备"的积极版本 — 不是止损,而是主动试错
- 与 `reality-check`: 后者评估"这个方案好不好",本 skill 把"评估"变成"行动"

## E — 可执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **检查可逆性**
- 完成标准: 用户能说出"如果错了,我能撤回/损失在 X 以内"
- 判停条件: 不可逆 → 不用本 skill,改用 `base-rate-forecast` + `values-decision`

   🔴 **CHECKPOINT**: 若用户说"代价很大但值得",提示他"代价是否可控?能否接受这个代价作为'试水成本'?"

2. **设计小规模试探**
- 完成标准: 用户能说出"我会做一个最小化的尝试 X,代价 Y,周期 Z"
- 关键: 试探要"可控"(保金斯基原则 2),不是"试试看就全力以赴"

3. **预设反馈信号**
- 完成标准: 用户能列出至少 1-3 个"什么信号说明值得加大投入"和"什么信号说明放弃"
- 判停条件: 若用户说不出反馈信号,提示他"没有反馈的试水等于没试水"

4. **执行 → 观察 → 调整**
- 完成标准: 用户在小规模试探后,根据反馈决定下一步(加大/放弃/调整方向)

   🛑 **STOP 条件**: 若用户在小规模试探后说"我还要再试一次"(拖延),提醒他"反馈已经足够,做决定;若反馈矛盾,扩大试水规模或回到 `base-rate-forecast`"

### if-fail 三段式兜底

| 失败信号 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 用户试水规模过大(代价不可控) | 用 🛑STOP: 保金斯基原则 2 要求"可控",缩小规模 | 调 `base-rate-forecast` 评估基础比率 |
| 试水反馈矛盾/不清楚 | 延长观察期(再试一次)或扩大试水规模 | 若仍矛盾,标注"领域本身不确定",接受"边走边看" |
| 用户陷入"试水瘫痪"(反复试不决) | 用 🔴CHECKPOINT: "试水的目的是决,不是不决。设定截止日期" | 调 `red-team` 强制做反向评估;若仍不决,接受这是价值观未明,调 `values-decision` |

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **不可逆决策**(婚姻/移民/已签约/重大健康):错误代价不可控
- **错误代价不可控**:任何试错可能造成不可恢复损失
- **纯执行细节**: 已经决定怎么做
- **基础比率极低的情况**:如成功率 0.1%,即使试水也意义不大 — 调 `base-rate-forecast`

### 作者在书中警告的失败模式

- **「一锤子买卖」(ce09)**: 选专业前不试水就大规模投入
- **「斯大林式不可控尝试」(ce10)**: 试水尺度失控+不关心反馈
- **「知易行难」(ce17)**: 试水原则简单但实操难
- **「试水不可逆」(ce20)**: 婚姻/移民/签约等无法小规模试水 — BOOK_OVERVIEW 批判段
- **「基础比率 vs 试水矛盾」(ce19)**: 两者适用场景不同 — 可逆选试水,不可逆选基础比率

### 作者的盲点 / 时代局限

- **「可控」假设错误代价可量化**: 实际很多试错代价是"心理/声誉/机会",难量化
- **「反馈」假设反馈可观察**: 实际很多决策反馈周期很长(创业 5+ 年)
- **「小规模试探」假设试探能代表真实场景**: 实际小规模试和大投入完全不同(如免费打杂 vs 真正上班)
- **与「3P 决策」的内在矛盾**: 60% CEO 决策无计划书,实干的"科学"在于力度不调研 — 但很多场景无法"先试"(如政策制定)

### 容易混淆的邻近方法论

- **「MVP」(最小可行产品)**: 创业场景的试水,本质相同
- **「Lean Startup」**: 精益创业,试水是其核心
- **「Pre-mortem」(预先验尸)**: 想象失败倒推原因,与试水不同(试水是真做,预先验尸是假想)
- **「小步快跑」**: 类似但缺少"反馈闭环"的纪律
